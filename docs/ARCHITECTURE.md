# 架构与信任边界

## 模块
CLI是业务写入口；Engine编排阶段和版本；Store管理文件、锁与原子替换；Providers只发文本HTTP请求；Dashboard只读取状态和指定成果路径。

## 数据流
new保存需求和流程快照 → prompt组合可信角色、当前要求和待分析资料并保存摘要 → import核对原任务输入或run返回后检查输入 → 校验章节后成为pending_review → 人工approve绑定输入、输出和前置批准摘要 → 开放下一阶段。

读取状态时重新计算有效性；需求、角色、成果和前置批准变更使相应下游变为stale。缓存仅在单次状态计算内使用，避免重复递归。

## 一致性
同项目使用独占.lock；写入同目录临时文件，fsync后os.replace。成果先写、状态后写，中断时摘要不匹配则旧批准失效。这不是跨文件数据库事务；恢复需备份或重建项目。看板可能在写窗口短暂显示stale，刷新即可。

## 网络与费用
密钥只来自环境变量。HTTPS端点主机明确允许，拒绝跳转，无工具执行，无自动重试。请求前计数，超时也可能已计费；只存顶层整数用量，不计算美元费用。错误不回显供应商正文。

## 信任
角色规则是可信配置，客户资料和上游成果是待审数据。Prompt不能保证抵御注入；程序通过不给模型执行工具权限和要求人工审核来控制边界。章节/哈希不证明技术或业务正确性。本机文件与审批依赖可信操作者，无身份认证和防篡改签名。

## 依赖决策
运行用标准库，不引入数据库、前端构建或模型SDK。浏览器QA使用环境提供的Playwright，不是产品运行依赖。GitHub Actions引用已核验的官方发布提交，只读token。跨机器服务、预算金额控制或执行沙箱须新立ADR并增加测试。
