# 产品范围和完成定义

## 目标与使用者
让管理者持有统一任务、事实、范围和验收定义，跨Agent移交时保持可复核证据。和乐或项目负责人负责商务和批准，业务、技术、实施、审查等角色负责成果。

## 功能
1. 项目编号唯一，需求、流程快照、成果与记录隔离。
2. delivery六阶段、engineering四阶段，每步包含角色和必需章节。
3. 离线演示明确标记，模拟审批不得转成正式批准。
4. Prompt导出和结果导入绑定输入；支持按角色选择三类文本API协议。
5. 所有正式成果先pending_review；人工approve后才能进入后续。
6. 输入、成果、角色规则或上游批准变更，相关成果变成stale。
7. 只读回环HTTP看板、指定交付预览、Markdown状态报告。
8. VS Code任务、Git工作树、Issue/PR规范与CI。

## 约束
Python3.11+标准库；项目写锁与原子文件替换。每项目最多20次远程尝试，失败也计数；每请求累计输入≤120KB、成果≤150KB、响应≤2MB；输出Token上限64—16384、超时配置1—120秒。次数和Token不是金额保证。

## 范围之外
自动修改代码、生产部署、采购付款、对外发送、多人远程协作、身份认证、完整秘密检测与业务正确性自动保证。审批姓名是操作者自报，哈希是版本漂移检查，拥有文件权限的人可改记录。

## 验收
tests覆盖两条离线流程、正式手工链路、门禁、过期成果、版本变化、网络协议、隐私路径和看板。真实供应商与用户凭证需要独立联调。验证证据见VALIDATION.md与最终PR CI。
