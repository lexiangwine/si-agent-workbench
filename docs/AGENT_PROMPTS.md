# 多 Agent 操作方式

## 文档协作
运行prompt导出角色、输入、上游成果、权限和完成定义。交给现有Agent生成Markdown，存workspace，再import与人审。不要仅传口头结论或遗漏上下文；事实冲突交业务负责人处理。

## 工程协作
读取AGENTS.md与docs/tasks/任务契约，在允许文件范围内用独立工作树实现。基础PR合并后，可用`bash scripts/new-agent-worktree.sh task-name`从origin/main创建agent/task-name。基础PR未合并时沿实现分支开发，避免取到空main。

执行Agent指令：“按任务契约实现目标，仅改允许文件。为每项完成定义提供真实测试证据。缺输入或范围冲突时报告阻塞。交接包括变更、文件、命令和结果、风险、下一动作。关联Issue提交PR，不合并或部署。”

审查Agent指令：“独立比较契约、实际diff和证据。分清已验证、推断和未检查；报告严重性、修复与复验条件。无实际测试不得声称通过；不能凭标题齐全放行。”

本次初始化没有调用并行子代理。本程序阶段按依赖和人审串行推进；用户可在不同Agent工作树中并行编码，本版本不提供自动并行调度或代码执行沙箱。
