# 本地启动与运维

## 启动
按README克隆、切分支、doctor、demo、serve。仅监听127.0.0.1，不发布公网；Ctrl+C停止，--port可改端口。VS Code打开工作区，si.python填写Python可执行文件。Windows可在终端用py -3；脚本需Git Bash或同等环境。

## 备份
workspace不入Git。经客户授权后通过安全渠道备份整个项目目录，包括需求、流程、状态、Prompt、成果和报告；密钥不写入项目。留存、删除与账号权限按项目约定处理。

## 排障
|问题|操作|
|---|---|
|项目已存在|换新编号，不覆盖真实项目|
|上游未批准|status检查，由负责人复核后approve|
|stale或过期Prompt|重新导出、复核、导入，再审批受影响的下游|
|缺章节|按契约二级标题补齐，内容仍需人审|
|缺Prompt元数据|先prompt，确认成果基于同版输入再import|
|.lock残留|先确认进程停止并备份，检查记录；确认无活跃写入者后人工删该锁|
|JSON/成果损坏|保留现场，从备份恢复或重建，不伪造批准|
|缺模型或凭证|本机配置变量，勿通过聊天提交密钥|
|HTTP错误或超时|核对供应商控制台、模型、端点；可能已计费，不自动重试|
|截断|缩小任务或按模型限制调整Token，再明确重跑|
|达到20次上限|复盘后新建明确范围的后续项目，保留原证据|

## 更新和回退
停止进程、备份workspace后更新已审核代码。项目保留流程快照；角色更新可能使既有审批失效，须复核。回退前检查state schema兼容，当前schema_version=1。不含服务器部署。

## CI和分支
quality在PR和功能分支运行Python3.11/3.12/3.13；contract检查PR正文。首次运行后可按账户能力配置保护，要求矩阵检查与人工审查。本次不改分支保护或生产设置。未合并基础PR前继续使用feat/workbench-foundation。
